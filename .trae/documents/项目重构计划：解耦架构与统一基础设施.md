通过对代码库的深入分析，我发现当前项目存在 UI 与业务逻辑高度耦合、代码重复（特别是日志和配置部分）以及一些健壮性问题。

为了提高项目的可维护性和扩展性，我制定了以下分阶段的重构计划：

### **第一阶段：基础设施统一与清理 (Infrastructure & Cleanup)**
> 目标：消除冗余代码，建立统一的配置和日志标准。

1.  **合并日志系统**：
    *   删除 `custom_logger.py`。
    *   全局统一使用 `my_logger.py`（基于 `loguru`），并确保所有模块（UI、API、下载逻辑）都通过单例模式获取日志实例。
2.  **统一配置管理**：
    *   创建 `config.py`，集中管理所有硬编码的路径（如默认下载目录 `~/Movies/yt-dlp`）、默认超时时间、重试次数等。
    *   将 `ui.py` 和 `api_server.py` 中的配置读取逻辑迁移到该模块。
3.  **工具类整理**：
    *   检查 `utils.py`，确保通用函数被正确复用，移除散落在各处的重复辅助函数。

### **第二阶段：核心逻辑解耦 (Core Logic Decoupling)**
> 目标：将下载业务逻辑从 UI 中剥离，使其可以被 API Server 和 UI 共享。

1.  **提取 `DownloadManager`**：
    *   创建一个独立于 UI 的 `DownloadManager` 类。
    *   将 `ui.py` 中的 `prepare_download_options` 方法和 `api_server.py` 中的类似逻辑合并到该类中。
    *   该类将负责生成 `yt-dlp` 配置 (`ydl_opts`) 和管理下载任务状态。
2.  **重构 API Server**：
    *   修改 `api_server.py` 以使用新的 `DownloadManager`，消除逻辑重复，确保 API 启动的下载任务与 GUI 行为一致。

### **第三阶段：UI 重构与通信优化 (UI Refactoring)**
> 目标：让 UI 变得“愚蠢”，只负责展示，不处理业务逻辑。

1.  **MVC/MVP 模式改造**：
    *   将 `ui.py` 中的 `YoutubeDownloader` 类瘦身，只保留界面初始化和事件绑定代码。
    *   将业务逻辑（如开始下载、处理进度）移至 Controller 层或 ViewModel。
2.  **Tab 组件解耦**：
    *   修改 `tabs/history_tab.py` 和 `tabs/settings_tab.py`，移除对 `main_window` 的直接引用。
    *   使用 PyQt 的 **Signal/Slot (信号与槽)** 机制进行通信。例如，当设置更改时，发送信号通知主窗口，而不是直接修改主窗口的属性。

### **第四阶段：健壮性与错误处理 (Robustness)**
> 目标：提高程序的稳定性和错误反馈质量。

1.  **线程安全优化**：
    *   修改 `download_thread.py`，移除不安全的 `self.terminate()` 调用。改用 `is_cancelled` 标志位或 `yt-dlp` 的回调钩子来优雅地停止下载。
2.  **异常处理增强**：
    *   在 `DownloadManager` 中捕获 `yt_dlp.utils.DownloadError` 等特定异常，返回结构化的错误代码，而不是在 UI 层笼统地捕获所有异常。
3.  **任务 ID 规范化**：
    *   使用 `uuid` 替代简单的递增数字来标识下载任务，防止并发或删除任务时 ID 冲突。

---

**建议执行顺序**：
建议从 **第一阶段（基础设施）** 开始，然后进行 **第二阶段（逻辑解耦）**。这两步能带来最立竿见影的代码质量提升，且风险相对较小。
